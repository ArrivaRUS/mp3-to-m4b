# 003 — Захардкоженная версия в футере + аффорданс кнопок в узкой строке

**Когда:** 2026-07-01, заход правок из real-test (после DMG 0.6). Три грабли за один цикл.

## Что случилось
1. **Футер показывал «0.1.0», хотя приложение было 0.6.** Человек установил 0.6, но в подписи внизу стояло «0.1.0». Бамп версии (`Tokens.appVersion`=0.6, `build-app.sh`, Info.plist) НЕ отразился в футере.
2. **В очереди, строка «Готово»:** «Открыть» ломалась посреди слова («Откры/ть»), «Собрать заново» переносилась и висела серой.
3. **«Собрать заново» человек счёл неактивной** и даже удалил готовый M4B, пытаясь её «включить» — хотя кнопка была кликабельна.

## Причины
1. Строка версии была **захардкожена литералом «0.1.0»** в ТРЁХ экранах (`SetupView`/`QueueView`/`StatusView`), а `Tokens.appVersion` в футере **не использовался**. Бамп трогал константу, которую никто не читал. Обнаружено только через `strings` по РЕАЛЬНОМУ бинарю (не по исходнику).
2. У `QButton` не было `.lineLimit(1)`/`.fixedSize` → в окне фикс-ширины 400pt лейблы переносились/рвались по слогам.
3. Стиль `.link` красил кнопку в `textMuted` (#9fb2bd, приглушённо-серый) — цвет читается как **disabled**, хотя кнопка `enabled`.

## Правило на будущее
- **Пользовательская версия — из ОДНОГО источника.** Любая версия-подпись обязана интерполировать `Tokens.appVersion`, а не литерал. Хардкод версии в UI = баг ожидания.
- **Провенанс версии проверять по АРТЕФАКТУ, не по исходнику.** `strings <app>/Contents/MacOS/<bin> | grep <version>` + Info.plist + рендер футера. «В исходнике 0.6» ≠ «в шипнутом бинаре 0.6». (Строки короче 4 символов `strings` не ловит — «0.6.1» ловит, «0.6» нет; смотри на отсутствие СТАРОЙ версии.)
- **Отгружаешь исправленный билд поверх забагованного с тем же номером — бампни patch.** 0.6→0.6.1: честный футер сразу говорит человеку, что он на исправленной сборке. Иначе version-identity снова размывается.
- **Строка фикс-ширины: кнопки держат intrinsic-ширину (`.lineLimit(1)`+`.fixedSize`), усекается ЗАГОЛОВОК** (`.lineLimit(1)`+`.truncationMode(.tail)`, `maxWidth:.infinity`). Действия важнее — они не должны переноситься/рваться.
- **Тесно для двух текстовых кнопок + заголовка → вторичную кнопку в ИКОНКУ** (SF Symbol + `.help`/a11y-label), заголовок тогда влезает целиком. Не жертвуй заголовком ради двух подписей.
- **Приглушённо-серый = «выключено» в глазах человека.** Кликабельный вторичный контрол должен нести ИНТЕРАКТИВНЫЙ цвет (акцент/бирюза), а не muted-серый. «Не競ирует с главной кнопкой» ≠ «выглядит мёртвой».
- **Симптом «не стартует + счётчик показывает N»** для folder-watch утилиты — это чаще дедуп уже-собранной книги (агент помнит done по содержимому), а не поломка. Проверяй `state.json`/манифесты/`events` на диске ПЕРЕД тем, как чинить «баг».
