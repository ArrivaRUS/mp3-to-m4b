# План: порт бинарного раннера fb2-to-epub → mp3-to-m4b (релиз 1.0) — Архитектор #1 (Claude)

> Дата: 2026-07-25. Донор: `../2026.06 fb2-to-epub` (схема принята и обкатана в бою,
> `arch/plan-binrunner-synthesis.md` донора). Решение человека: **портируем схему соседа**,
> не проектируем с нуля. Документ написан под адверсариальный разбор Codex:
> допущения и точки отказа — явные, отклонения от донора — помечены `⚠️ DEVIATION`.

## Цель

На macOS 26 (Tahoe) tccd атрибутирует TCC/FDA-запрос launchd-агента к **Mach-O-образу**
процесса. Наш `ProgramArguments[0]` — shebang-скрипт `bin/runner.sh`
(`packaging/installer.sh:60`, `:270-272`), его образ — `/bin/bash` (platform binary) →
**молчаливый deny**. Грант, который наш же установщик просит выдать (`installer.sh:363-366`),
не работает никогда; watch-папка по умолчанию `~/Desktop/mp3-to-m4b` (`installer.sh:169`) —
TCC-зона. Диагноз донора: `<СОСЕД>/.patches/020-tahoe-fda-script-grant-dead-real-not-panel.md`.

Релиз 1.0 = четыре куска, порядок приземления важен:

1. **Бинарный раннер** — замороженный Mach-O helper как PA0 (порт донора).
2. **Само-починка plist** — фактический PA0 через `plutil`, решение ДО показа UI.
3. **Онбординг доступа** — детект в агенте → state.json → edge-pop → карточка → кнопка «путь».
4. **StartInterval** — наш собственный фикс авто-старта (у донора его НЕТ и брать оттуда нечего).

## Решения (с обоснованием)

### Р1. Helper спавнит `bin/runner.sh` как ребёнка (вариант «минимальная дельта») — ПРИНЯТО

Сравнивались два варианта:

| | A: helper → `/bin/bash runner.sh` (ребёнок) | B: helper сам резолвит python и спавнит `python3 -m agent` |
|---|---|---|
| Дельта от боевого C донора | только строка-имя соседнего файла + префиксы сообщений | новый непроверенный C-код: цепочка фолбэков python, сборка PYTHONPATH, обработка отсутствия venv |
| Байт-стабильность | резолв python остаётся в shell → helper НИКОГДА не меняется при смене venv/фолбэков | любая правка резолва = пересборка = новый cdhash = молчаливая смерть грантов у всех |
| Переезд venv | правится `runner.sh`/installer (свободно мутируемые) | либо логика заморожена навсегда, либо re-grant всем |
| Окружение из plist | наследуется как есть (donor parity: `environ` в `posix_spawn`) | то же, но фолбэк-ветки при протухшем `PYTHON3` — в замороженном C |
| Соответствие боевой цепочке | helper→bash→python — ровно донорская форма (helper→bash watcher→python3/Calibre, доказано E1-логом tccd) | новая форма, не обкатанная |

**Выбор: A.** Единственная валюта этой конструкции — неизменность байтов helper'а
(`ad-hoc DR = cdhash`, донор `PROVENANCE.md:8-13`). Всё, что может захотеть меняться
(резолв python, PYTHONPATH, venv-путь), обязано жить ВНЕ замороженного файла.
После порта `runner.sh` **демотируется** из FDA-цели в обычный дочерний скрипт: его
байты можно менять в каждом релизе безнаказанно — это главный выигрыш.

Ключевые инварианты варианта A (load-bearing, в шапку .c и в комменты runner.sh):

- **Helper: spawn+wait, НЕ exec** (донор `.c:14-20`) — exec заменил бы Mach-O-образ на
  `/bin/bash` и вернул баг. Helper живёт весь ран как responsible-родитель.
- **runner.sh: `exec "$PYTHON3" -m agent` ОСТАЁТСЯ ЗАКОННЫМ** (`bin/runner.sh:55`).
  Запрет exec касается только PA0-процесса. Ребёнок может exec'аться сколько угодно:
  pid остаётся ребёнком helper'а, атрибуция — к responsible-процессу job'а (helper).
  Итоговое дерево: `launchd → mp3-to-m4b-agent (helper, жив) → python3 (бывший bash, exec) → ffmpeg`.
  Это допущение A1 (см. Допущения) — T0-гейт проверяет его ФАКТИЧЕСКИМ чтением, до интеграции.
- Резолв соседнего файла — `_NSGetExecutablePath` + `realpath`, не argv[0] (донор `.c:76-88`).
- Форвардинг SIGTERM/SIGINT/SIGHUP ребёнку + зеркалирование exit-кода (донор `.c:63-70, :114-148`).

**Имя: `mp3-to-m4b-agent`.** Уроки донора (синтез, решение №1 + patch 020): имя в FDA-панели
обязано отличаться и от мёртвой строки (у нас потенциально `runner.sh`), и — на этой машине —
от `fb2-to-epub-agent` донора, чтобы человек не сказал «уже включено». Раскладка:
исходник `packaging/agent-src/mp3-to-m4b-agent.c`, замороженный артефакт
`packaging/mp3-to-m4b-agent` (коммитится в git), установка → `$BIN_DIR/mp3-to-m4b-agent`
(сосед `runner.sh`). Helper ищет рядом с собой файл `runner.sh` (наш аналог донорского
`fb2-to-epub-watcher.sh`, `.c:104`).

`⚠️ DEVIATION-1 (микрофикс до заморозки).` Донорский `PROVENANCE.md:23-41` документирует два
теоретических окна класса tini и предписывает: «при гипотетической будущей пересборке учесть».
Наш артефакт собирается ВПЕРВЫЕ (байты всё равно новые — другие строки), поэтому окно №1
(pid-reuse после `waitpid`) закрываем сразу: `if (w == pid) { g_child = 0; break; }`.
Окно №2 (коллапс пре-spawn сигналов, один слот `g_pending_sig`) оставляем как у донора —
тот же осознанный компромисс tini/dumb-init, launchd шлёт один SIGTERM.
Атака Codex «отклонился от боевых байтов» отбивается так: боевыми являются ДИЗАЙН и цепочка,
а не байты (байты у нас в любом случае свои); фикс №1 рекомендован ревью самого донора.

**Разовая сборка + freeze-guard** — порт `build-once.sh` донора (`:38-51` страж, `:53-67`
clang `-arch arm64 -arch x86_64 -mmacosx-version-min=11.0` → strip → `codesign -s -`).
Страж-переменная: `MP3TOM4B_AGENT_REBUILD_I_UNDERSTAND=1`. После сборки — заполнить
`PROVENANCE.md` (sha256, size, cdhash обоих слайсов, DR, окружение сборки) по форме донора
(`PROVENANCE.md:43-71`). Пересборка = осознанное редкое событие + предупреждение в release notes.

### Р2. Само-починка plist: решение синхронно ДО UI; починка — гибрид

Донор (v1.0.3, рабочее дерево): `installedRunnerIsHelper()` читает фактический PA0 через
`plutil` НЕ через фолбэчный `runnerPath()` — фолбэк вернул бы ожидаемый путь и замаскировал
протухший plist (`EngineClient+Status.swift:632-647`); условие
`needsRefresh = байты differ || PA0 ≠ helper` (`:727-731`); запуск синхронно до создания UI
(`main.swift:549-571`), потому что CTA карточки копирует PA0 из plist.

Наш порт:

- **Решение (детект)** — синхронно в `applicationDidFinishLaunching` до выбора landing-экрана
  (наш `app/main.swift:3855-3862` уже считает `shouldAutoUpdateAgent()` синхронно — расширяем):
  `needsRepair = freshness == .outdated (есть, agent/*.py) || bundledHelperDiffers || bundledRunnerDiffers || PA0 ≠ installedHelperPath`.
  - `bundledHelperDiffers` / `bundledRunnerDiffers`: байт-сравнение Resources ↔ `$BIN_DIR`
    (наш `AgentUpdate` фингерпринтит ТОЛЬКО `agent/*.py` — helper и runner.sh сегодня вне
    контракта свежести; это дыра донор закрывал списком `engineScriptNames` — закрываем).
  - PA0-проверка — прямой `plutil -extract ProgramArguments.0 raw`, без фолбэка (урок донора).
- **Починка, случай 1 — «PA0-only»** (все байты совпали, PA0 ≠ helper: окно сбоя installer /
  предзаложенный артефакт — донорский тест C9 `run-agent-helper-tests.sh:303-330`):
  запускаем bundled installer **СИНХРОННО до UI** (донорская семантика). Цена: venv уже жив →
  проверка `import PIL` + перегенерация plist + перезагрузка агента ≈ 1–2 с. Редкий случай.
- **Починка, случай 2 — «байты протухли»** (обычный апдейт приложения): наш существующий
  **асинхронный** путь с экраном `.updating` (`main.swift:3857-3859`, `:4014+`) — БЕЗ изменений UX.
  `⚠️ DEVIATION-2 (async вместо донорского sync).` У донора installer без venv — синхронный
  запуск дёшев. У нас холодный/битый venv = `pip install Pillow` с сетью (десятки секунд) —
  блокировать этим показ окна нельзя. Компенсирующий **инвариант вместо синхронности**:
  **FolderAccess-поверхность не рендерится, пока (updatePhase ∈ {running, failed}) ИЛИ
  (фактический PA0 ≠ helper)** — роутер приоритетов `agentRepair > folderAccess > normal`
  (порт донорского `StatusRouter`, `StateModel.swift:228-236`, с нашей семантикой первого слота).
  Пояс и подтяжки: кнопка «скопировать путь» читает PA0 живьём `plutil`-ом В МОМЕНТ нажатия —
  протухший путь не может попасть в буфер даже при баге роутера. Инвариант закрывается тестом
  (см. Тест-план), это главная точка атаки Codex — признаём явно.
- **Строгий резолв watch-dir СОХРАНЯЕМ** (наш `currentWatchDir()`: state.json →
  `EnvironmentVariables.MP3TOM4B_WATCH_DIR` → nil, БЕЗ дефолта — `main.swift:3886-3912`;
  он лучше донорского `readWatchDir() ?? default`, `EngineClient+Status.swift:734`).
  Правило для случая 1: PA0 кривой, а watch-dir неизвестен → синхронно НЕ чиним (нельзя
  рисковать перепойнтом на дефолт), уходим в существующий `.failed`-экран с текстом
  «обновите через Настройки» (`main.swift:4024`). Молчаливый перепойнт запрещён.

### Р3. Онбординг доступа (порт с упрощением: наш агент — уже Python)

Донор делает probe bash-heredoc'ом в python (`fb2-to-epub-watcher.sh:359-378`) и атомарный RMW
двух ключей (`:388-448`). Нам проще: агент и есть Python, а `state.json` пересобирается целиком
каждым сканом (`scan.py:1050-1067`) — RMW не нужен.

- **Probe в агенте** (у приложения ДРУГАЯ TCC-identity — детект обязан жить в агенте):
  `probe_watch_dir_access(watch)` в `scan.py` — `os.listdir` (EAGER, одна классификация):
  `PermissionError → "denied"` (EPERM от TCC и EACCES от chmod слиты НАРОЧНО — chmod-симуляция
  в тестах ведёт себя как боевой TCC, донор `:350-356`); `ENOENT/ENOTDIR → "missing"`;
  прочие OSError → `"missing"` + errno в лог; иначе `"ok"`. Read-only, без probe-файлов.
- **Вызов в начале `run_scan`** (наш аналог донорского «после лока, до engine-check»,
  `:1391-1397`): probe ДО `scan_watch_folder`, результат — в `build_state`. Сегодняшнее
  поведение при deny: `watch.is_dir()` глотает EPERM → `return [], None` (`scan.py:944-948`) —
  витрина молча пустеет. Новые правила:
  - `agent.folder_access` + `agent.folder_access_ts` пишутся В КАЖДЫЙ скан (ts — доказательство
    свежей проверки для «Проверить снова»);
  - `folder_access_ts` — ISO-8601 UTC c `Z` и **суб-секундной точностью**, opaque-токен
    (урок ревью A2 донора `:403-410`: усечение до секунд коллапсирует свежий probe с нажатым);
  - **при `denied` витрина замораживается**: `books`/`pending_groups` переносятся из prev
    state как есть (у донора это выходило бесплатно из RMW; у нас пересборка бы ВЫТЕРЛА книги
    и Status мигал бы пустотой под карточкой);
  - `refresh_showcase` (перепроекция без скана, `scan.py:1515+`) probe НЕ гоняет —
    **переносит** прошлые `folder_access`/`_ts` (иначе поля мигают absent посреди сборки).
- **Edge-pop**: переход `prev ≠ denied → denied` (prev уже читается в `run_scan:1487`) →
  один подъём приложения через СУЩЕСТВУЮЩИЙ нудж-механизм `_nudge_app`
  (`scan.py:1396-1444`): наследуем сим `MP3TOM4B_NUDGE_CMD` (рекордер в тестах), глушение
  по `MP3TOM4B_SUPPORT_DIR` (селфчеки не поднимают боевое приложение) и журналирование.
  Ledger «notified» НЕ используем — донорская семантика «фронт по prev-значению» достаточна
  (denied→denied на каждом StartInterval-тике попов не плодит).
- **Swift-модель** — порт донора: enum `FolderAccess` (rawValue-декод, неизвестное → nil →
  нет поверхности, `StateModel.swift:66-105` донора); наш `AgentInfo` (`app/StateModel.swift:180-198`)
  расширяется полями с толерантным декодом (мусор в поле не роняет весь блок agent);
  чистые `FolderRecheck.evaluate` (принимает исход ТОЛЬКО при ts ≠ нажатого) +
  `terminalRecheckDissolves` (A1: живой флаг ушёл из denied → прибитая терминальная карточка
  растворяется) — `:210-259` донора, портируются дословно.
- **UI — `FolderAccessCard` в НАШИХ токенах** (`app/Tokens.swift`), 4 подачи как у донора
  (`FolderAccessCard.swift:51`): `blocker` (Status без истории), `banner` (Status с историей —
  история есть ⇔ `totals.built > 0 || !books.isEmpty`), `setupStep` (display-only шаг в Setup,
  наш `SetupView` — рядом с существующим футноутом `:642`), `settingsRow` (замещает пассивную
  строку FDA в Настройках `main.swift:987+` ТОЛЬКО пока denied). Автомат
  `denied/checking/stillDenied/timeout` — как у донора (`:37-48`).
- **Кнопка «Открыть настройки и скопировать путь»**: путь = **фактический PA0 из plist**
  через `plutil` (порт `EngineClient.runnerPath()` донора `:317-325`; фолбэк —
  `<supportRoot>/bin/mp3-to-m4b-agent`, чтобы скрэтч-тесты не тыкались в боевой путь),
  НЕ хардкод; клипборд — с верификацией записи и повтором + ack «Путь скопирован ✓»
  (донор fix #2, `main.swift:1311-1339`); затем существующий `openFullDiskAccess()`
  (`main.swift:1163-1171`). Текст шага 3 — константа-литерал `mp3-to-m4b-agent`,
  пришпиленная name-parity-проверкой (донор, секция D тестов).
- **«Проверить снова»**: `launchctl kickstart gui/<uid>/<label>` (БЕЗ `-k` — SIGKILL стрендит
  чужие раны, урок харнеса донора patch 020) → ждать СМЕНЫ `folder_access_ts` (poll state,
  таймаут ~10 с → `.timeout`). StartInterval даёт естественный добивочный probe ≤60 с даже
  если kickstart не сработал.

### Р4. StartInterval — наш фикс авто-старта (у донора НЕТ, это не порт)

Диагноз: `WatchPaths` на iCloud-Desktop после логина инертен; агент run-once
(`agent/__main__.py:15-16` — «then we exit; launchd re-launches on WatchPaths event») →
без периодики спит до ручного пере-bootstrap. Фикс: `StartInterval` в `gen_plist`.

- **Значение: 60.** Худший case подбора дропнутой книги при мёртвых WatchPaths — ~1 мин
  (продуктовое обещание «положил папку — окно всплыло само» держится); цена холостого рана
  `python3 -m agent` ≈ 0.2–0.4 c CPU раз в минуту — пренебрежимо. 120/300 c ухудшают UX без
  осязаемой экономии. Решение человека может поменять число — механика та же.
- **Конфликты с п.1/п.2 — нет**: launchd держит ОДИН экземпляр на label — пока идёт длинная
  ffmpeg-сборка (процесс жив), тики просто пропускаются; `ThrottleInterval 5` остаётся;
  `KeepAlive` НЕ добавляем (рестарт-шторма нет). Helper спавнится каждый тик — spawn+wait
  тривиален. С п.3 синергия: probe свежий ≤60 c → карточка сама растворяется в течение минуты
  после выдачи гранта, даже без «Проверить снова».
- **Побочка, которую обязаны закрыть в том же milestone**: рост журналов.
  (a) `events.jsonl`: `agent_started` пишется каждый ран (`state.py:79+`, fsync) →
  ~1440 записей/сутки ≈ 50 МБ/год без предела. Фикс: size-cap ротация в `append_event`
  (порог ~5 МБ → `events.jsonl.1`, хранить один бэкап); контракт «каждый запуск наблюдаем»
  сохраняется. (b) `mp3-to-m4b.log` (StandardOutPath): холостой ран должен печатать МЕНЬШЕ
  (баннер-печати `__main__.py:42-44` перевести на «печатай только если что-то произошло»
  либо тот же size-cap на стороне агента при старте). Без этого 1.0 тихо замусорит диск.
- **Регресс-selfcheck**: в сгенерированном plist есть `StartInterval` = 60 (integer),
  `RunAtLoad` = true, `WatchPaths` — ровно 2, `ProgramArguments` — ровно 1 элемент
  (страж от «двухэлементного» следа ручного репойнта, замеченного в живом plist донора —
  это НЕ проектное решение, копируем одноэлементный вариант).

## Milestones (порядок приземления, зависимости)

```
M-A ──► M-B ──► M-D ──► M-E ──► M-F
         │                ▲
         └──► M-C ────────┘      (M-C ∥ M-D — независимы)
```

- **M-A. Замороженный helper + T0-гейт** (блокирует всё).
  Порт `.c` (имя, сосед `runner.sh`, микрофикс №1) + `build-once.sh` (страж
  `MP3TOM4B_AGENT_REBUILD_I_UNDERSTAND`) + однократная сборка + `PROVENANCE.md` (заполнен
  фактическими sha/cdhash) + артефакт в git. **T0-гейт (см. раздел) обязан пройти ДО M-B.**
  ⛔ Если T0 показывает subject ≠ helper — СТОП, к человеку.
- **M-B. Интеграция installer + build + журналы** (зависит от M-A).
  installer.sh: `AGENT_BIN_DST`, `find_agent_bin`, укладка cmp-preserve + sha fail-closed +
  точечный `xattr -d` ТОЛЬКО после sha; `gen_plist`: PA0 = helper (один элемент) +
  `StartInterval 60`; текст FDA-подсказки → путь helper'а. build-app.sh: helper → Resources +
  **release-blocking байт-страж после codesign** (донор `build-app.sh:283-302`).
  runner.sh: переписать шапку (демотирован в ребёнка; exec законен; FDA-цель — helper).
  Ротация events.jsonl + тихий холостой ран. Selfcheck-расширения (см. Тест-план).
- **M-C. Агент: probe + поля state + edge-pop** (независим от M-B; можно параллельно).
  `scan.py`: probe, поля, заморозка витрины при denied, carry-forward в `refresh_showcase`,
  нудж на фронте denied. Новый `selfcheck_fda.py`. Работает и под старым runner-PA0 —
  поля просто честно скажут denied.
- **M-D. Swift: само-починка** (зависит от M-A/M-B: имя, семантика installer).

## Миграция существующих установок

Кто мигрирует: живая установка человека (v0.9: PA0=`runner.sh`, watch = `~/Desktop/mp3-to-m4b`
на iCloud-Desktop) + возможные внешние установки (repo и DMG публичны).

1. **Что происходит при обновлении**: запуск нового .app → синхронный детект: байты agent/*.py
   и helper протухли/отсутствуют → экран `.updating` → bundled installer с ТЕКУЩЕЙ папкой
   (строгий резолв, дефолт запрещён) → helper уложен (sha-проверен), plist перепечён:
   PA0 = helper, + StartInterval → bootstrap/kickstart → агент фирится → probe → `denied`
   (грант новому субъекту ещё не выдан) → edge-pop поднимает приложение → карточка.
2. **Один новый грант неизбежен**: старый субъект был `/bin/bash` (грант скрипту мёртв как
   класс — переносить нечего). Пользователь узнаёт из карточки (п.3): 3 шага, путь уже в
   буфере, включить `mp3-to-m4b-agent`. Это и есть связка «п.1 до п.3»: карточка обязана
   называть НОВЫЙ бинарь, поэтому UI-milestone идёт после installer-milestone.
3. **Rollback — проще донорского**: у донора runner.sh оставался «ещё один релиз» как
   отдельный legacy-файл (синтез, решение №2). У нас `runner.sh` — ЖИВОЙ ребёнок цепочки
   и шипится всегда; rollback = перепойнт PA0 обратно на `runner.sh` (одна команда plutil +
   пере-bootstrap, зафиксировать в release notes для разработчика). Отдельный legacy-артефакт
   не нужен. Старая строка `runner.sh` в FDA-панели пользователя может остаться висеть —
   безвредна, имена не путаются.
4. **Свежая установка** (Setup, первый запуск): installer сразу кладёт helper и печёт
   правильный plist — карточка появится только если папка в TCC-зоне и гранта нет.
5. **R1b для человека** (донор, решение №8): грант боевому пути выдаётся ОДИН раз до релиза,
   проверяется фактическим действием под тест-меткой → сам релиз проходит для него без
   единого похода в настройки.

## Тест-план

в scratch (паттерн `selfcheck_installer_repoint.py`); боевое дерево не трогается; launchctl —

## Риски и точки отказа

1. **Байты helper'а изменятся в конвейере** (пересборка «на автомате», codesign --deep в
   будущем тулчейне, iCloud-эвикция файла в repo, git-фильтры) → грант умирает у всех молча.
   Заслоны: freeze-guard в build-once; байт-страж сборки (release-blocking); sha fail-closed в
   installer; selfcheck сверки с PROVENANCE. Остаточный риск: правка .c «по мелочи» без
   понимания → PROVENANCE-шапка + страж требуют явный env-флаг.
2. **venv-python переедет/сломается** → в варианте A это НЕ касается helper'а: чинится
   runner.sh/installer (свободно мутируемые), грант живёт. Протухший `PYTHON3` в plist
   покрыт фолбэк-цепочкой runner.sh (`:29-39`). Это главный аргумент против варианта B.
3. **Plist наполовину обновлён** (installer упал между укладкой файлов и mv plist): сам plist
   атомарен (temp + `mv`, `installer.sh:309-318`), а межфайловое окно закрывает PA0-self-heal
   при следующем запуске приложения (C9-аналог). Остаточное окно: приложение не запускают
   неделями — агент живёт на старом PA0 (deny), карточки нет, т.к. и приложения нет; закрыто
   поведенчески: первый же запуск чинит.
4. **Гонки авто-апдейта**: одновременно launch-автоапдейт, Settings-«Обновить», синхронный
   PA0-ремонт. Требование: single-flight по `agentUpdatePhase` (второй запуск при `.running`
   запрещён) — проверить существующую защиту и закрепить. Два installer'а параллельно
   идемпотентны по файлам (cmp/sha), но bootout/bootstrap могут потолкаться — не смертельно,
   следующий проход чинит; всё равно не допускаем.
5. **DEVIATION-2 (async вместо sync)**: если инвариант подавления сломают будущей правкой
   роутера — пользователь может скопировать мёртвый путь. Заслоны: live-чтение PA0 в момент
   нажатия + инвариант-тест + комментарий-предупреждение у роутера. Это самая честная точка
   атаки Codex; альтернатива (полный sync как у донора) отвергнута из-за venv/pip-блокировки
   запуска до десятков секунд.
6. **StartInterval-побочки**: рост events.jsonl/лога (закрыто ротацией/тихим раном — M-B);
   тик во время длинной сборки (закрыто семантикой launchd «один экземпляр на label»);
   state.json перезаписывается каждый тик → лишний UI-рефреш раз в минуту (дёшево).
7. **tccd снова поменяет модель атрибуции** (macOS 27+) → T0-скрипт остаётся в repo как
   перегоняемый смок после мажорных апдейтов ОС.
8. **Intel-слайс не проверяется локально** (машина arm64): lipo гарантирует наличие слайса,
   поведенческий смок — через Rosetta если доступен, иначе риск принимаем (как донор, №6).
9. **Панель FDA врёт** → все инструкции/QA формулируются через фактическое действие
   (probe/конвертация), скриншот панели никогда не является доказательством (patch 020).
10. **Заморозка витрины при denied** скрывает реальное исчезновение книг, пока доступа нет →
    осознанно: при deny агент ФИЗИЧЕСКИ не может знать правду; после гранта первый же скан
    приводит витрину к реальности.

## Допущения (явно, под атаку)

- **A1.** Атрибуция TCC: для launchd-job'а субъект — Mach-O-образ PA0-процесса; дети
  (включая ребёнка, сделавшего exec bash→python3) атрибутируются к responsible-родителю.
  У донора доказано для helper→bash→python3(grandchild)/Calibre (E1-лог + бой);
  наша цепочка helper→python3(child после exec)→ffmpeg — та же модель на уровень короче.
  Проверяется T0.1/T0.2 ДО интеграции; если exec-ребёнок вдруг атрибутируется иначе — T0
  это покажет немедленно (probe выдаст denied при выданном гранте и subject уедет).
- **A2.** `StartInterval` сосуществует с `WatchPaths`+`RunAtLoad`; launchd не запускает второй
  экземпляр label, пока жив первый. Подтверждается ребут-тестом и наблюдением тиков в логе.
- **A3.** Грант ad-hoc-подписанному helper'у пришпилен к пути И байтам (cdhash-DR) и живёт
  через обновления, пока installer соблюдает cmp-preserve (донор доказал в бою; наш T0.3 —
  негативный контроль).
- **A4.** `codesign --force --deep` по бандлу НЕ мутирует Mach-O в `Contents/Resources`
  (эмпирика донора, НЕ контракт Apple) → потому байт-страж после подписи release-blocking,
  а не «на всякий случай».
- **A5.** Квантин на установленном helper'е допустимо снимать точечно ПОСЛЕ sha-сверки;
  exec заквантиненного ad-hoc бинаря launchd'ом у донора проходил и без снятия (strip —
  страховка, не несущая стена).
- **A6.** Пути стабильны: `~/Library/Application Support/mp3-to-m4b/bin/` не переезжает в 1.x;
  переезд = новый субъект = re-grant всем (запрещён без отдельного решения).
- **A7.** Probe `os.listdir` — достаточная классификация: TCC-deny всегда даёт
  PermissionError на listdir watch-папки (донорская эмпирика), а слияние EPERM/EACCES не
  создаёт ложных `denied` в жизни (chmod-кейс у реального пользователя экзотичен, и remedy
  тот же — «дай доступ»).
- **A8.** 60-секундный тик энергетически незаметен (run-once python ~0.3 c) и не душит iCloud
