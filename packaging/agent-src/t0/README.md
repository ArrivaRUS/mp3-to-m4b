# T0 — гейт «кому macOS отдаёт решение о доступе»

Один вопрос: субъектом TCC-решения становится наш замороженный Mach-O helper
или `/bin/bash`? Пока ответ не получен, M1–M7 не начинаются (план v2, §3, §4).

## Как запускать

```
packaging/agent-src/t0/t0.sh              # подготовка + ячейки до гранта, затем
                                          # инструкция человеку (путь уже в буфере)
packaging/agent-src/t0/t0.sh verify       # после гранта: ячейки B, C, D (+E, +iCloud)
packaging/agent-src/t0/t0.sh verify-off   # после того как человек ВЫКЛЮЧИЛ тумблер
packaging/agent-src/t0/t0.sh status       # что сейчас на диске и загружено
packaging/agent-src/t0/t0.sh clean        # снести T0-дерево, plist и папки-пробы
packaging/agent-src/t0/t0.sh exec-form    # T0.5, справочно, в гейт не входит
```

Человеку достаётся ровно один заход: добавить файл в «Полный доступ к диску»,
включить тумблер, потом выключить. Всё остальное — внутри скрипта.

## Что здесь лежит

| Файл | Роль |
|---|---|
| `t0.sh` | харнес: печёт plist, гоняет ячейки, сводит вердикт, убирает за собой |
| `t0-runner.sh` | двойник боевого `bin/runner.sh` (та же топология, другая полезная нагрузка); `t0.sh` проверяет их структурный паритет |
| `t0_probe.py` | проба: пишет pid'ы, читает защищённую папку, классифицирует `ok/denied/missing/blocked` под сторожевым таймером |
| `t0_log.py` | сшивает строки журнала tccd по ОДНОМУ `msgID` и говорит, кто был субъектом |

## Изоляция

Тестовая метка `com.arrivarus.mp3tom4b.t0`, тестовый корень
`~/Library/Application Support/mp3-to-m4b-t0`, тестовое ИМЯ файла
`mp3-to-m4b-agent-t0`. Харнес отказывается стартовать, если любое из них
совпало с боевым. T0-грант — намеренно НЕ боевой: боевой (R1b) выдаётся
отдельно в M7, и поэтому ячейка с порчей байт ничем ему не угрожает.

## Две зоны проверки — это важно

- **GATE** — `~/Downloads/mp3tom4b-t0-probe`: под защитой TCC, но локальная.
  Здесь вопрос гейта получает быстрый и чистый ответ, поэтому вердикт строится
  на ней.
- **CLOUD** — `~/Desktop/mp3tom4b-t0-probe`: под защитой TCC И в домене iCloud
  FileProvider. С тем же самым грантом и тем же helper'ом чтение здесь виснет,
  а в GATE-зоне отвечает за 5 мс. Это свойство папки, а не helper'а, поэтому
  зона идёт отдельной диагностикой и никогда не красит гейт.

## Чему верим

Панель «Полный доступ к диску» доказательством НЕ является — она не отрисовывает
свежие записи (урок соседа `020B`). Верим двум вещам: фактическому действию
(проба реально прочитала содержимое `marker.txt`) и журналу tccd, сшитому по
одному `msgID`. `launchctl print` доказывает загруженный PA0, но не субъекта;
`codesign` доказывает образ на диске, но не цепочку ответственности.

Результаты прогона на macOS 26.5.2 — в `../PROVENANCE.md`, раздел «T0 gate».
